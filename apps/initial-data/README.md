# دریافت داده‌ی اولیه

این app مستقل Vite+ در `apps/initial-data` قرار دارد و نام workspace آن `@akiraminafit/initial-data`
است. کد، تست‌ها، فایل `.env`، خروجی دانلود و تنظیمات build داخل همین پوشه نگه داشته می‌شوند. به
`apps/api` وابسته نیست؛ فقط از قرارداد ورودی و جداول دیتابیس در `packages/contracts` و `packages/db`
استفاده می‌کند.

این ابزار صفحات عمومی [بانک حرکات مسترجیم](https://mrgym.ir/exercises/) را دریافت می‌کند و یک بستهٔ
مستقل با `manifest.json`، ویدیوها، تصاویر و متن فارسی می‌سازد. دریافت بسته به دیتابیس یا اجرای API
نیاز ندارد. import فایل‌ها را در S3/MinIO تنظیم‌شدهٔ پروژه می‌گذارد و حرکات را به کتابخانهٔ **یک
مربی موجود** اضافه می‌کند؛ ساختار فعلی پروژه کتابخانهٔ جداگانه برای هر مربی دارد.

## آماده‌سازی

از ریشهٔ پروژه اجرا کنید:

```bash
npm install
cp apps/initial-data/.env.example apps/initial-data/.env
```

دریافت داده‌ها با درخواست HTTP و پردازش HTML، XML و CSS داخل Node.js انجام می‌شود. به Chromium،
Playwright، محیط گرافیکی یا نصب وابستگی‌های سیستمی مرورگر نیازی نیست. رنگ‌های CSS و گرادیان‌های
نقشهٔ عضلات در SVG خروجی حفظ می‌شوند. اسکریپت‌ها و منابع جانبی صفحه اجرا یا بارگیری نمی‌شوند.

برای import باید جداول دیتابیس و bucket رسانه آماده باشند. تنظیمات `DATABASE_URL`، `S3_*` و
`COACH_EMAIL` را در `apps/initial-data/.env` قرار دهید؛ اتصال دیتابیس و bucket باید با نرم‌افزار
اصلی یکسان باشد. تنظیمات از `.env` اصلی پروژه خوانده نمی‌شوند. فایل دیگری را با مسیر صریح `ENV_FILE`
می‌توان انتخاب کرد. اگر مربی هنوز وجود ندارد، ابتدا آن را از نرم‌افزار اصلی یا فرمان
`npm run db:seed` بسازید. ابزار import برای حساب موجود به رمز عبور مدیر نیاز ندارد.

## دریافت و import با یک فرمان

در `vp run` فلگ‌ها را مستقیم بعد از نام فرمان بنویسید؛ به جداکنندهٔ `--` نیاز نیست. اگر با npm اجرا
می‌کنید، شکل معادل `npm run initial-data:sync -- [options]` است. CLI جداکنندهٔ اضافی بعد از نام
فرمان را هم می‌پذیرد.

```bash
vp run initial-data:sync
```

تمام لینک‌های یکتای حرکت از همهٔ `exercise-sitemap*.xml`های معرفی‌شده در sitemap اصلی کشف می‌شوند.
با `--category` فقط لینک‌های صفحهٔ همان دسته دریافت می‌شوند. فهرست صفحهٔ اصلی که فقط بخشی از حرکات
را دارد، مبنای شمارش نیست. فایل‌ها در `apps/initial-data/data/mrgym` قرار می‌گیرند و سپس برای مربی
`COACH_EMAIL` وارد می‌شوند. این پوشه در Git ثبت نمی‌شود. دریافت کل بانک با توجه به حجم ویدیوها
زمان‌بر است؛ پیش‌فرض حداقل یک ثانیه بین شروع درخواست‌های منبع فاصله می‌گذارد و درخواست‌ها ترتیبی
هستند.

برای مربی دیگر:

```bash
vp run initial-data:sync --coach-email coach@example.com
```

## دریافت مستقل و انتقال به سرور

```bash
vp run initial-data:scrape
```

کل پوشهٔ `apps/initial-data/data/mrgym` را به سرور منتقل کنید. روی سرور، پس از نصب وابستگی‌ها و
تنظیم `apps/initial-data/.env`، با یک فرمان فایل‌ها و داده‌ها را وارد کنید:

```bash
vp run initial-data:import
```

بررسی بسته بدون هیچ آپلود، اتصال دیتابیس یا تغییر داده:

```bash
vp run initial-data:import --dry-run
```

## آزمایش با صفحهٔ نمونه

```bash
vp run initial-data:sync --bundle /tmp/mrgym-sample --url https://mrgym.ir/exercise/dumbbell-bench-press/
```

برای چند صفحه، `--url` را تکرار کنید. برای دریافت تعداد محدود از sitemap:

```bash
vp run initial-data:scrape --bundle /tmp/mrgym-first-ten --limit 10
```

برای دریافت فقط پنج حرکت از دستهٔ سینه:

```bash
vp run initial-data:scrape --bundle /tmp/mrgym-chest-test --category chest --limit 5
```

برای دریافت و import همان نمونه با یک فرمان:

```bash
vp run initial-data:sync --bundle /tmp/mrgym-chest-test --category chest --limit 5
```

مقدار `--category` نام انتهایی مسیر دسته (مثل `chest`) یا آدرس کامل صفحهٔ آن است؛ برای پیدا کردن
دسته‌ها از [فهرست حرکات منبع](https://mrgym.ir/exercises/) استفاده کنید. برای چند دسته، فلگ را تکرار
کنید؛ لینک‌های تکراری حذف می‌شوند و `--limit` پس از ترکیب دسته‌ها روی تعداد کل حرکات اعمال می‌شود:

```bash
vp run initial-data:scrape --bundle /tmp/mrgym-test --category chest --category back --limit 10
```

فلگ‌های `--category` و `--limit` برای `scrape` و `sync` هستند. `--category` با `--url` قابل ترکیب
نیست؛ یکی از این دو روش انتخاب را استفاده کنید. بدون `--limit` همهٔ حرکات انتخاب‌شده دریافت می‌شوند.
برای آزمایش از `--bundle` جداگانه استفاده کنید؛ اجرای دوباره با انتخاب کوچک‌تر در همان مسیر،
manifest را به انتخاب جدید محدود می‌کند.

بستهٔ محدود، فقط برای همان انتخاب کامل است؛ `discoveredCount` و `selectedUrls` دامنهٔ دریافت را نشان
می‌دهند. فرمان import همهٔ رکوردهای بسته را وارد می‌کند.

مسیر پیش‌فرض بسته داخل خود app، یعنی `apps/initial-data/data/mrgym` است. اگر `--bundle` بدهید، مسیر
نسبی آن از ریشهٔ monorepo محاسبه می‌شود. بسته‌های قبلی با قالب فعلی سازگارند؛ برای نمونه:

```bash
vp run initial-data:import --bundle data/exercises/mrgym
```

## اطلاعات و رسانه

- عنوان فارسی و انگلیسی، توضیح، مراحل اجرا، عضلهٔ اصلی، تجهیزات و سطح استخراج می‌شوند.
- اطلاعات اصلی/کمکی عضلات از `#mgx-focus[data-muscles]` و متن بخش‌های صفحه در بسته حفظ می‌شوند.
- فایل ویدیوی داخل `#mgx-player`/`.mgx-player`/`mgx-player`، شامل `data-video` و ویژگی‌های lazy،
  فایل اصلی است و با `sortOrder=0` ثبت می‌شود؛ ویدیوهای پیشنهادشدهٔ سایر بخش‌ها وارد نمی‌شوند.
- نمای جلو و پشت از `#mgx-focus .mgx-anat figure[data-side] > svg` استخراج می‌شوند. پردازشگر DOM در
  Node.js رنگ، stroke و opacity را از CSS محاسبه و به خود عناصر SVG می‌نویسد؛ گرادیان‌های SVG خواهر
  در هر خروجی کپی و پس‌زمینهٔ تیره اضافه می‌شود. فایل SVG مستقل از CSS سایت در گالری فعلی برنامه و
  حالت آفلاین قابل نمایش است.
- پوستر ویدیو تصویر اصلی حرکت و thumbnail ویدیو است. پس از ویدیوی اصلی با `sortOrder=1` و قبل از
  تصاویر عضلات ثبت می‌شود؛ import ترتیب بسته‌های قدیمی را هم اصلاح می‌کند. کارت کتابخانه و انتخاب
  حرکت در برنامه‌ساز، پوستر ویدیو را در اولویت نمایش قرار می‌دهند و نقشهٔ عضلات در گالری می‌ماند.
- `media/` فایل‌های قابل نمایش، `records/` متن اصلی کامل، و `manifest.json` دادهٔ آمادهٔ import،
  مسیرهای نسبی، MIME، اندازه و SHA-256 فایل‌ها را نگه می‌دارند.
- فیلدهای توضیح و دستورالعمل ورودی برنامه به‌ترتیب به ۱۰۰۰ و ۴۰۰۰ نویسه محدود می‌شوند؛ متن کامل در
  `records/<slug>.json` حفظ می‌شود. سایر فیلدهای نامعتبر به‌جای حدس یا حذف خاموش به عنوان شکست
  دریافت گزارش می‌شوند. فایل‌های بزرگ‌تر از سقف فعلی برنامه، ۱۰۰ MiB، رد می‌شوند.

## ادامهٔ دریافت و اجرای دوباره

با همان فرمان و همان `--bundle` دوباره اجرا کنید. فایل‌های تأییدشده با اندازه و SHA-256 استفادهٔ
مجدد می‌شوند و موارد ناموفق/ناقص دوباره دریافت می‌شوند. برای دریافت مجدد صفحات و فایل‌ها `--refresh`
بدهید. با `--delay-ms 2000` فاصلهٔ درخواست‌ها را افزایش دهید؛ حداقل ۲۵۰ است.

شکست هر صفحه در `manifest.json` ثبت می‌شود، سایر صفحات ادامه پیدا می‌کنند و خروجی فرمان ناموفق خواهد
بود. `sync` در این وضعیت import را شروع نمی‌کند. برای وارد کردن آگاهانهٔ فقط رکوردهای موفق از
`vp run initial-data:import --allow-partial` استفاده کنید.

پیش از import، کل manifest و اندازه و checksum همهٔ فایل‌ها بررسی می‌شود. شناسهٔ هر حرکت از منبع و
شناسهٔ مربی به شکل قطعی ساخته می‌شود؛ اجرای دوباره رکورد تکراری نمی‌سازد. import داده و رسانه‌های
همان حرکت واردشده را به‌روزرسانی می‌کند و عکس‌ها/ویدیوهای دستی مربی را حفظ می‌کند. وضعیت آرشیو حرکت
موجود حفظ می‌شود. فایل‌های S3 با کلید شامل checksum ذخیره می‌شوند؛ نسخهٔ قبلی تا commit تراکنش معتبر
می‌ماند. فایل‌های قدیمی S3 خودکار حذف نمی‌شوند.

هر حرکت و رسانه‌هایش یک تراکنش دارند؛ کل بانک یک تراکنش واحد نیست. در قطع import، حرکت‌های قبلی باقی
می‌مانند و اجرای دوباره به شکل امن ادامه می‌دهد. هر فرمان را برای یک پوشهٔ بسته به‌صورت هم‌زمان با
فرمان دیگری که همان پوشه را می‌نویسد اجرا نکنید.

اگر میزبان ویدیو به‌جای MP4 صفحهٔ بررسی مرورگر یا CAPTCHA برگرداند، ابزار آن را ویدیو ذخیره نمی‌کند.
متن استخراج‌شده در `records/<slug>.source.json` و SVGهای جلو/پشت همچنان نگه داشته می‌شوند؛ حرکت بدون
ویدیوی اصلی وارد بستهٔ قابل import نمی‌شود. دریافت را از اتصالی که ویدیوی منبع در آن قابل دسترس است
دوباره اجرا کنید. نصب مرورگر یا تغییر پردازشگر HTML محدودیت دسترسی میزبان ویدیو را برطرف نمی‌کند.

## بررسی ابزار

```bash
vp run initial-data:test
npm run typecheck
```

برای اجرای مستقیم از داخل app:

```bash
cd apps/initial-data
vp run scrape
vp run import
vp run test
```

build مستقل با `vp pack` و تنظیمات `vite.config.ts` همین app انجام می‌شود:

```bash
vp run @akiraminafit/initial-data#build
vp run @akiraminafit/initial-data#start scrape --help
```

تست اختیاری import با PostgreSQL واقعی و سرور آزمایشی S3 نیز وجود دارد. فقط آدرس یک دیتابیس موقت با
نامی منتهی به `_test` را پس از ساخت جداول با `db:push` به `CATALOG_TEST_DATABASE_URL` بدهید و
`vp run initial-data:test` را اجرا کنید؛ این تست به دیتابیس پروژه نیاز ندارد.

## حذف ابزار

پوشهٔ `apps/initial-data`، چهار فرمان `initial-data:*` در `package.json` ریشه و ورودی lint مربوط به
`apps/initial-data/**` در `vite.config.ts` ریشه را حذف و `npm install` را اجرا کنید. ارجاع‌های
راهنما در READMEهای ریشه و `docs/exercise-catalog.fa.md` را هم می‌توان حذف کرد. هیچ تغییری در کد
API، وب یا جداول دیتابیس لازم نیست. داده‌ها و رسانه‌هایی که قبلاً import شده‌اند باقی می‌مانند؛
فایل‌های دانلودی محلی در پوشهٔ خود app هستند.
